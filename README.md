# 听见进步 · 我的王陆语料库

个人雅思听写练习页面，部署目标：[ielts-wanglu-dictation.github.io](https://ielts-wanglu-dictation.github.io/)。

完整保留上游的 **5,873 个词条、32 个小节、第 3 / 4 / 5 / 11 章**，包含英文、音标、中文释义和原始顺序。上游 README 中“8 个章节”的说法与实际语料不符，此处以原始数据为准。

## 功能

- 整节 / 20 / 50 / 100 词分组、自选词序范围、顺序和乱序听写。
- 结算页一键继续下一组，首页与小节页自动接续已提交的进度；例如第 1–50 词完成后接着第 51–100 词，末组不足时按实际数量练习。进度由已有历史逐词记录恢复，已练完后明确显示完成，不自动回到第一词。
- 开始听写即播放首词；Enter 跳到下一题并播放，Shift+Enter 返回上一题并播放，F2 / Alt+R 重听，Esc 停止。最后一题 Enter 只移动到提交按钮，不自动提交。支持行内播放、聚焦播放、连播、英美口音、语速、重复、间隔和语音选择。
- 本机英语语音优先，在线词典及备用发音；支持短语、缩写和原语料注释的发音归一化。
- 答案错位修正：插入空行、答案上移、撤销。插入时保护已有末题答案。
- 检查答案、再次修改、提交后重新批改。检查不重复计入错词或历史。
- 错词 / 全部批改、历史详情、正确率趋势、整组或错词重练。
- 每日目标、连续练习统计，以北京时间 06:00 为新学习日的起点。
- 错词搜索、按小节筛选 / 分组、按错误次数或最近时间排序；全部、到期、巩固中和已掌握筛选。
- 每词可点击“模糊”或按 F4 标记，跟随草稿、历史及 JSON 备份保存。答对但模糊也加入复习，不计为错误；支持模糊词筛选、模糊次数排序、单独重练及 CSV 导出。模糊答对不增加掌握度，清晰答对后取消当前模糊状态，历史标记次数保留。
- 间隔复习：答对依次安排 1 / 3 / 7 / 14 / 30 / 60 天后复习，错误立即回到待复习。连续答对 3 次标记已掌握，仍会按时到期。
- 自动保存草稿并续练、浅色 / 深色主题、手机布局和键盘操作。
- JSON 完整备份与恢复，兼容原版 `{hist, wb}` / `wl2_*` / `wl3_*`；导入先校验再确认，替换前下载当前备份。
- 错词 CSV 导出；页面和语料离线缓存、Web App 安装入口由浏览器提供。
- 可选 GitHub 账号登录与私有仓库备份：本地即时保存、联网自动上传、每天北京时间 04:00 归档；恢复前校验内容和版本，有冲突时保留双方供选择。

## 使用

首页点击“开始今日练习”，或在“语料练习”选择小节与范围。建议先使用设置页“测试语音”。练习答案、错词和偏好首先保存在当前浏览器的 `localStorage`；即使离线或未登录，也可以继续练习和导出 JSON。

听写时无需逐行点击喇叭：输入答案后直接按 Enter。页面的“聚焦播放”开关只控制鼠标或 Tab 进入输入框时是否朗读，不影响 Enter 换题播放。部分笔记本使用 F2 / F4 需同时按 Fn，也可以点击对应按钮或用 Alt+R 重听。

“继续听写”恢复尚未提交的草稿；“继续练习”开始该小节下一组尚未练习的词。顺序与乱序的进度都按实际词条编号计算；错词和模糊专项复习不推进小节进度。存在跳段练习时先补最前面的空档，旧版只保留汇总成绩的记录无法推断缺失的词序。

GitHub 备份是可选功能。完成 [授权服务配置](backup-service/README.md) 后，在“设置与备份”用 GitHub 登录，浏览器把学习状态自动上传到专用私有仓库。授权服务未配置时，登录按钮不可用，不影响本地练习与文件备份。网页中不填写 GitHub 密钥。

每个学习日为北京时间 06:00 至次日 05:59:59。当天第一次联网打开时检查私有仓库的最新状态；有本机尚未上传的改动时，不会直接用旧备份覆盖。04:00 的 GitHub Action 只能归档已经上传的记录：关闭浏览器前未联网上传的内容，要等下次联网才能备份。Action 的定时运行可能有延迟，06:00 检查读取 `latest.json`，不依赖当天定时任务是否准时完成。

原生语音取决于设备所安装的英语语音。在线发音会向 DictionaryAPI / Youdao / Google 等服务发送当前英文词条，不发送你的答案和学习记录。这些免费服务可能受网络、限流和浏览器播放策略影响。此页面不包含原书配套录音。

首次联网打开后缓存页面和词库。离线语音仍需本机英语语音支持。浏览器可能回收网站缓存或存储，重要记录请备份。静态练习页无需后端；可选的登录服务没有学习数据库，只访问专用私有 GitHub 仓库。登录会话单独保存，不会放入学习数据导出文件或备份仓库。

## 本地运行与验证

需要 Node.js 22+ 和 Python 3；运行时无 npm 依赖。

```sh
npm test
npm run test:service
npm run check
python -m http.server 4173 --bind 127.0.0.1
```

在浏览器打开 `http://127.0.0.1:4173`。请通过 HTTP 使用，ES modules 与 Service Worker 不支持直接双击 HTML 的 `file://` 模式。

GitHub Pages 自动部署见 [DEPLOYMENT.md](DEPLOYMENT.md)。应用为相对路径的纯静态页面，可部署在域名根路径或项目子路径。

## 文件

`app.js` 界面与练习流程；`core.js` 批改 / 统计 / 备份 / 复习纯函数；`audio.js` 发音；`data.js` 完整语料；`backup.js` 登录与同步；`backup-config.js` 公开的服务地址；`backup-service/` 独立授权服务；`styles.css` 响应式样式；`sw.js` 离线缓存；`tests/` 核心功能测试。生产构建自动根据全部资源生成缓存版本，无需手动修改版本；直接预览源码时可清除本地测试缓存后刷新。
